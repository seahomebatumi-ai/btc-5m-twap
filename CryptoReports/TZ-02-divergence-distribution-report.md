## 6. What could not be implemented as written

1. **The Release asset upload.** §3 requires the Parquet as a GitHub Release asset and
   §5.3 requires publishing before reporting. The tag `tz-01a-dataset` and the
   SHA-256 are published as specified. The asset is not: the Release API call was
   refused twice by the local sandbox, which blocks reading the credential out of
   the git remote and sending it to `api.github.com`. This is not a missing
   credential — the same credential pushed this branch and this tag — so §5.3's
   "resolve that first" has no remote action to take. It is recorded here rather
   than worked around.

2. **`research/twap-divergence.py` was not on `main`.** §6.5 requires asserting its hash, but
   the file lived only on branch `tz-01a-twap-divergence-corrected` at `ea9290b`. It was
   restored from that commit byte-identical — both hashes match the TZ-01a report, as §6.5
   asks — and carried forward on this branch together with the self-test and the TZ-01a
   `.gitignore`, so the check is reproducible on `main`. Nothing in either file was changed.

3. **§2.3's denominator is ambiguous.** "Percentage of all observations" can mean the 210,234
   at that `tau` or the full 1,051,170. Both columns are reported in measurements 3 and 4
   rather than choosing.

4. **§4 does not name a direction.** "The tradeable subset at `T = 0.05`" could mean either
   direction or one of the two rows measurement 4 produces. All three are reported; §4 above
   records that the verdict is identical under all of them.

5. **§2.6 is stated as one number but the gate needs another.** The section asks for the
   count of observations qualifying at more than one checkpoint in an interval; §4 needs the
   count of distinct intervals. Both are reported, along with the full per-interval
   distribution, for all five checkpoints and for the four gate checkpoints separately.

Nothing else in §§1–6 was unsatisfiable. No §3 quantity was re-derived, re-implemented or
altered, and the TZ-01 archive was not read.
